# 채팅 종료
1. 작업 채팅:
   - 명세의 완료 기준 확인. 테스트·빌드 결과 기록(실패 시 그대로).
   - `docs/tasks/<이름>.md` 끝에 `## 결과` 추가: 바뀐 파일, 완료 기준별 충족 여부, 결정 사항, 남은 일, 다른 작업에 영향 주는 점.
   - `docs/chats.md` 상태 "완료 보고".
2. 메인 채팅:
   - `docs/status.md` 갱신: 완료/다음 할 일/미결정. 새 채팅이 이것만 읽고 이어갈 수 있게.
   - 확정 결정은 `docs/plan.md`에 반영.
   - `docs/chats.md` 갱신.
3. 커밋 → 작업 브랜치 푸시 → `main` 대상 PR 생성(GitHub MCP) → 바로 병합(사용자 사전 승인됨). 충돌 시 `main`을 리베이스해 해결 후 병합, 해결 불가면 사용자에게 보고.
4. 사용자 안내:
   - 작업 채팅: 결과 요약 3줄 이내(세부는 명세 `## 결과`에 있으므로 반복 금지) → 마지막 줄 `완료. 메인 채팅에서 확인 요청.` (기준 미충족 시 `미완료: <이유>`). 새 채팅 열기 안내는 하지 않음(메인 담당).
   - 메인 채팅: 아래 형식으로 새 메인 채팅 안내.
     ````
     이 채팅 보관 후 새 채팅을 열고 첫 프롬프트로 입력:
     ```
     이 채팅은 메인 채팅이야.
     ```
     ````
